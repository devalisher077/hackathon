## Что делает V14

- Собственные Triton-кернелы RMSNorm, NF4, RoPE, vocabulary loss/entropy и сложения градиентов MLP.
- Обработка непустых строк внутри frozen MLP, компактное хранение активаций и общей embedding/head-таблицы.
- FP16-хранение logits с FP32-вычислением метрик, совместный перенос небольших метрик на CPU.
- Кэш распакованных frozen attention-весов; LoRA и dropout сохраняются.
- Параллельная компиляция и подготовка Triton launchers внутри измеряемого процесса.

Организаторский SwiGLU сохранён и не считается собственным кернелом.
Необязательный кэш NF4 scales отключён. Настройки задачи и измерительный код не изменены.

## Запуск

Импортировать `templates/kaggle_notebook.ipynb` в Kaggle, выбрать T4 и включить Internet.
Ноутбук устанавливает зависимости, использует публичный starter checkout и встраивает
именно текущую V14; публикация нового коммита для этого запуска не требуется.
В уже подготовленном Kaggle можно вставить целиком `kaggle-v14-update.py` из родительской папки.
Скрипт сохраняет предыдущую solution и запускает тесты, два повторения base/solution, eval и проверки.

Из корня репозитория на CUDA/T4:

```bash
python -m pytest solution -q
python harness/run_task.py --repeats 2 --out runs_v14
python harness/check_rules.py --result runs_v14/result.json
```

## Структура

- `solution/` — V14 и её тесты.
- `harness/`, `task/`, `tests/` — исходные проверки и фиксированная задача хакатона.
- `templates/` — готовый Kaggle-ноутбук V14.
- `verification/` — статус и контрольные суммы V14.
- `.venv/` — используемое локальное окружение, не включается в архив/Git.

Задача: Soup 0.77.0, Qwen2.5-1.5B-Instruct, NF4, LoRA r=16, batch 4,
64 шага, до 512 токенов, одна T4. Все 10 проверок обязательны, в том числе минимум
5% времени собственных Triton-кернелов в каждом запуске. Правила реализованы
в `harness/check_rules.py`; ready-made kernel libraries и изменения задачи запрещены.
